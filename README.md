# NSA Cleaning LLC — website

Static, SEO-first marketing site for **NSA Cleaning LLC** (Watervliet, NY — serving Albany to Lake George). The only opt-in is the GoHighLevel chat widget.
Reference used for structure: nettoyageprocleaning.com. Facts, brand rules and copy constraints live in [docs/CONTENT.md](docs/CONTENT.md).

## Stack

| Piece | Choice | Why |
|---|---|---|
| Pages | Plain HTML rendered by `build.mjs` (zero dependencies) | Fastest possible pages, full control over SEO markup |
| Styling | One hand-written `src/styles.css`, inlined at build time | No render-blocking CSS request |
| Fonts | Plus Jakarta Sans, self-hosted (`public/fonts`) | No third-party requests, no layout shift |
| Images | WebP renditions generated by `scripts/optimize-images.py` from `raw-images/` | Small, responsive `srcset` images with alt text in `raw-images/manifest.json` |
| Lead capture | GoHighLevel chat widget (loaded on every page) | The client's CRM receives the lead directly; no backend, no secrets on the site |
| Hosting | Vercel (`vercel.json`) — a Cloudflare Pages adapter is in `functions/` | HTTPS forced automatically, HSTS + CSP + security headers configured |
| Analytics | GA4 loaded **only after** cookie consent (`public/main.js`) | Cookie banner + Consent Mode |

## Project layout

```
site.config.json      business data, nav, siteUrl, GA id, chat widget id
src/layout.html       HTML shell: all SEO/OG/Twitter meta, icons, JSON-LD, inline CSS
src/partials/         header, footer, cookie-banner, icons
src/pages/*.html      one file per URL; starts with <!--@meta {json} -->
src/styles.css        the design system (see docs/DESIGN.md)
public/               copied to dist/ as-is (images, fonts, main.js, icons, og-image.jpg, manifest)
scripts/              serve, screenshots, lighthouse, link check, image optimizer
docs/                 CONTENT.md (facts), DESIGN.md (design system), screenshots, audit reports
```

## Commands

```bash
npm install                 # dev tools only (puppeteer-core, lighthouse, html-validate)
npm run build               # → dist/ (+ sitemap.xml, robots.txt)
npm run serve               # preview dist/ at http://localhost:4000
npm run check               # broken internal links / anchors
scripts/lighthouse.sh http://localhost:4000/ docs/lh-home mobile
python3 scripts/optimize-images.py   # regenerate WebP renditions from raw-images/ + manifest
```

Page front matter example:

```html
<!--@meta
{ "title": "Deep Cleaning in Albany, NY | NSA Cleaning LLC",
  "description": "…140–160 chars…",
  "schema": [{ "@context": "https://schema.org", "@type": "Service", "...": "..." }],

```
`schema` accepts `"@business"` to inject the LocalBusiness block from `site.config.json`. `"noindex": true` keeps a page out of the sitemap and adds a noindex meta.

## Environment variables

Copy `.env.example` → `.env` locally; on Vercel set them under *Settings → Environment Variables*.

| Variable | Where | Purpose |
|---|---|---|
| `SITE_URL` | build | Public URL (canonical, sitemap, OG). Overrides `site.config.json`. |
| `GA_MEASUREMENT_ID` | build | GA4 id (`G-XXXXXXX`). Empty = analytics off. |
| `GHL_CHAT_WIDGET_ID` | build (public) | GoHighLevel chat widget id. Also settable as `ghlChatWidgetId` in `site.config.json` (currently `6ac7e06f1cb832596cd2237d`, NSA's sub-account). Empty = no widget, and the quote buttons are plain links to `/contact`. |
| `PHOTO_PLACEHOLDERS` | build | `0` hides the gray "Photo coming soon" blocks. Default (unset) shows them. Set it to `0` in Vercel before launch, once the client sends the missing photos listed in [docs/FOTOS-PEDIR.md](docs/FOTOS-PEDIR.md). |

Nothing secret is ever shipped to the browser: there are no server-side secrets at all. The build only bakes `SITE_URL`, `GA_MEASUREMENT_ID` and the public chat widget id.

## Lead capture (GoHighLevel chat widget)

The site has **no forms at all**: no `<form>`, no iframe, no `/api` endpoint. The GoHighLevel chat widget is the only opt-in, loaded on every page from `src/layout.html`.

- Every "Get a Free Quote" button renders as `<a href="/contact" data-quote-open>`. `public/main.js` intercepts the click and calls `window.leadConnector.chatWidget.openWidget()` (the widget's public API). The widget script loads async, so a click that lands before it is ready waits up to 4 s; if it never appears the button follows its href. Without JavaScript the button is a plain link to `/contact`.
- `/?quote` and `#quote` open the chat on load, which is handy for ads and email links.
- The widget renders in an open shadow root with its bubble at `bottom:20px`, which on phones covers the sticky `.mobile-cta` bar. CSS from the page can't reach inside, so `main.js` injects a `<style>` into the shadow root that raises the bubble by `--chat-lift` (set in `styles.css` below 900px, 0 on desktop). Only the closed state moves; the open panel keeps the widget's own mobile layout.
- `vercel.json`'s Content-Security-Policy allows `*.leadconnectorhq.com`, `*.msgsndr.com` and Cloudflare Turnstile (the widget uses it). If the widget stops loading in production, check the browser console for CSP errors first.
- Analytics: `main.js` fires `open_chat_widget` on each quote button click. The conversation itself happens in GoHighLevel and is tracked there.
- The widget's SMS consent text is mirrored in the Privacy Policy ("Text messages (SMS)") and the Terms, as A2P 10DLC registration requires.

## Production (GitHub Pages, lp.nsacleaningllc.com)

The live site is **https://lp.nsacleaningllc.com**, served by GitHub Pages from the `gh-pages` branch of `Rdavifelix/nsa-cleaning-site`. DNS (Cloudflare): `lp` CNAME → `rdavifelix.github.io`. The apex and `www` belong to a GoHighLevel site, not this repo.

Deploy from a clone whose `origin` is that repo:

```bash
CUSTOM_DOMAIN=lp.nsacleaningllc.com GIT_NAME="Your Name" GIT_EMAIL="you@example.com" scripts/deploy-pages.sh
```

This builds without `PREVIEW` (indexable), at the root, writes the `CNAME` file and force-pushes `gh-pages`. GitHub Pages ignores `vercel.json`, so its security headers and CSP do not apply there.

## Deploy (Vercel)

1. Push this folder to a GitHub repo (`git add -A && git commit -m "NSA Cleaning site" && gh repo create nsa-cleaning-site --private --source . --push`).
2. In Vercel: *Add New → Project → Import* the repo. Framework preset: **Other**. Build command and output dir are read from `vercel.json`.
3. Add the environment variables above. Redeploy.
4. *Settings → Domains*: add `nsacleaningllc.com` (available as of 2026-09-12) and `www.nsacleaningllc.com` (redirect www → apex). Vercel issues the TLS certificate and redirects HTTP → HTTPS automatically; the `Strict-Transport-Security` header in `vercel.json` makes browsers stay on HTTPS.
5. Set `SITE_URL=https://lp.nsacleaningllc.com` and redeploy so canonical/sitemap URLs match the domain.
6. Google Search Console: verify the domain, submit `https://lp.nsacleaningllc.com/sitemap.xml`.
7. Google Business Profile: use the exact NAP from `site.config.json` (321 25th St, Watervliet, NY 12189 · (407) 728-0523) so it matches the site's LocalBusiness schema.

### Analytics
Create a GA4 property, set `GA_MEASUREMENT_ID`, redeploy. The cookie banner and the footer *Cookie settings* button only render when `GA_MEASUREMENT_ID` is set. GA only loads after the visitor clicks *Accept*; *Decline* keeps the site cookie-free (and, after a previous *Accept*, disables the tag on the current page and expires the `_ga` cookies). Events sent: `click_call`, `click_email`, `cta_quote_*`, `open_chat_widget`.

## Client preview (GitHub Pages)

Live at **https://kauankamil-rgb.github.io/nsa-cleaning-site/** — a preview for showing the client, not the production site.

- Built with `PREVIEW=1`, so every page carries `noindex, nofollow` and `robots.txt` disallows all crawlers. It will not be indexed and cannot compete with the real domain later.
- `BASE_PATH=/nsa-cleaning-site` rewrites root-relative URLs so the site works from the subpath.
- The chat widget works on the preview too: leads that come in through it are real and land in the client's GoHighLevel account.
- Everything works: navigation and dropdowns, mobile menu, cookie banner, before/after slider, FAQ accordion, custom 404, sitemap.

Redeploy after any change: `GIT_NAME="Your Name" GIT_EMAIL="you@example.com" scripts/deploy-pages.sh` (builds and force-pushes to the `gh-pages` branch).

For production, deploy the plain `node build.mjs` output on Vercel. See **Deploy (Vercel)** below.

## Editing content
- Business facts (phone, hours, cities, prices) → `site.config.json` (used by header, footer, schema, and pages via `{{site.business.*}}`).
- Copy → `src/pages/*.html`. Keep the `<!--@meta -->` block valid JSON.
- Images → drop originals in `raw-images/`, add an entry to `raw-images/manifest.json`, run `python3 scripts/optimize-images.py`.
- Legal pages → `src/pages/privacy-policy.html`, `src/pages/terms-and-conditions.html`.
